# WoW: Forever API research

Evidence dated 2026-11-20. The local `wowf` executable reports `1.60.1.70959`. The pinned mirror of Blizzard's extracted Forever interface identifies that build. TOC Interface `16001` is corroborated by CraftAtlas's Forever manifest and Atraeau's `70790` API export. Record the fourth return of `GetBuildInfo()` in the actual client to confirm the build and TOC pair. Blizzard's [Forever launch recap](https://worldofwarcraft.blizzard.com/en-gb/news/24303862/) establishes product context.

## Capability matrix

Available means the capability has a source definition or clear implementation in this snapshot. Available with restrictions means the source documents secret or scoped behavior. Runtime limits remain pending wherever explicitly listed. No gameplay test has been run.

The development diagnostic implements the probes under `/da diag`. Values labelled missing, secret, restricted, failed or unavailable are preserved as status fields. A lightweight combat-start sample inspects Current damage; outside combat the recorder samples supported categories and bounded historical detail at combat end, after relevant events or on request. The report supplies aggregate and field coverage evidence for the matrix, with outcome and timing questions remaining open until exercised in Forever.

| Capability | Status | Source observation and runtime check |
| --- | --- | --- |
| `C_DamageMeter` availability | Available with restrictions | `IsDamageMeterAvailable()` returns capability and reason. Check service availability and whether the native meter must be enabled on this client. |
| Session catalogue | Available | `GetAvailableCombatSessions()` returns session ID, name and optional duration. Compare list snapshots for retention, reset, insertion order and ID reuse. |
| Aggregate metric reads | Available with restrictions | `GetCombatSessionFromID(sessionID, type)` and `GetCombatSessionFromType(sessionType, type)` are marked secret in combat. Returned fields include `combatSources`, `totalAmount`, `maxAmount` and optional `durationSeconds`. Test aggregate and source independently. |
| Session-scoped duration | Available with restrictions | `GetSessionDurationSeconds(sessionType)` returns optional duration. Historical durations also appear in catalogue and per-ID data. Compare actual meter duration with combat events. |
| Player rows | Available with restrictions | Names and GUIDs are conditionally secret, class token and local-player flag are marked never secret, spec icon explicitly secret. A field marked never secret does not guarantee a readable enclosing table. Check safe availability and match to party token GUIDs only when readable. |
| Damage, DPS, damage taken and avoidable damage | Available with restrictions | The four separate meter types exist. Aggregate damage taken per second depends on measured numerator/time semantics. Avoidable damage depends on Blizzard's classification. |
| Healing, HPS and absorbs | Available with restrictions | `HealingDone`, `Hps` and `Absorbs` exist. The storage enum names a combined healing/absorb category. Verify overlap, effective healing and absorb attribution before reporting derived totals. |
| Interrupts, dispels and deaths | Available with restrictions | Enum types exist. Rows can advertise `deathRecapID` and `deathTimeSeconds`. Validate their per-metric meaning and joinability. |
| Enemy damage taken | Available with restrictions | `EnemyDamageTaken` is an enemy-oriented aggregate candidate. It does not establish player-by-target totals or a boss-only split. Test a mixed pull. |
| Spell detail | Available with restrictions | `GetCombatSessionSourceFromID(sessionID, type, sourceGUID, sourceCreatureID)` accepts optional source identifiers. The type-based variant takes `sessionType` first. Detail returns spell aggregates. Test only with readable caller-owned arguments. |
| Healing received, self versus other | Pending validation | Generated schema advertises `combatSpellDetails` with unit name, class, flags and amount. It declares a single target-detail shape and no recipient GUID. Observe the actual shape, coverage and whether two same-name or same-class targets can be distinguished. No reconstruction is assumed. |
| Mitigation, damage absorbed on the recipient, overheal and resurrections | Not available as direct meter types | No corresponding enum or documented field supplies these as distinct metrics on this snapshot. `Absorbs` does not imply incoming mitigation. Record alternatives only after a dedicated verified source exists. |
| Fight duration, active player time and intra-fight series | Pending validation | Session duration is documented. There is no event-by-event or player-active duration in these session structures. Start with whole-segment samples only. |
| Instance and roster | Available with restrictions | `GetInstanceInfo()` gives type, difficulty ID and map/instance ID. `UnitGUID` and class/role APIs are candidates per party token. Instance ID need not identify a new copy and party role need not imply spec. Verify portalling, manual entry and roster replacement. |
| Boss attempts | Pending validation | `ENCOUNTER_START` and `ENCOUNTER_END` define encounter ID, name, difficulty, group size and numeric outcome on end. Check actual emission in Forever dungeons, wipes and mixed pulls. |
| Completion | Pending validation | `LFG_COMPLETION_REWARD` is documented. An event for queued completion does not establish completion after manual entry. Test both and preserve an explicit finish. |
| Session finalization, duplicates, reset and reload | Pending validation | An event's presence does not prove the server has delivered final data. Test order after combat, bounded retries, native UI reset observed passively, reload and how many sessions survive. |

The addon has no supported source for raw restricted payloads and will not depend on them. The diagnostic can record the public restriction flag when available. External file parsing is a separate project change. |
| Native UI component creation and line widgets | Pending validation | Shared templates and frame `CreateLine` appear in source. Runtime construction, safe mixins and visuals need client tests. |

## Runtime safety

Inspect `issecretvalue` and `canaccessvalue` before interpreting values, and `canaccesstable` before indexing or iteration. Guard each nested value separately, fail closed for restricted probes when required predicates are missing, and only copy allowlisted readable data. Treat an error handler as a way to report call failure. It cannot make a secret readable. Never format, compare, serialize or retain a secret value. A successful call can return unreadable contents. A nil or restricted field always stays distinct from a legitimate zero. Record predicate outcomes and counts in opt-in diagnostics instead of raw names, GUIDs or payloads.

Allowlisted candidate events are `ADDON_LOADED`, `PLAYER_LOGIN`, `PLAYER_LOGOUT`, `PLAYER_ENTERING_WORLD`, `ZONE_CHANGED_NEW_AREA`, `GROUP_ROSTER_UPDATE`, `PLAYER_REGEN_DISABLED`, `PLAYER_REGEN_ENABLED`, `ENCOUNTER_START`, `ENCOUNTER_END`, `LFG_COMPLETION_REWARD`, `DAMAGE_METER_COMBAT_SESSION_UPDATED`, `DAMAGE_METER_CURRENT_SESSION_UPDATED` and `DAMAGE_METER_RESET`. The generated historical update event includes metric type and session ID. Record registration separately from real delivery. Track login and reload flags and compare event clocks only within the same session. Never call `ResetAllCombatSessions` or require a CVar change.

## Source inspection and comparison

- The pinned [Blizzard API export](https://github.com/reckhou/WoWBlzCode/tree/acb81d6eece0bd7f221456a634a54904ba0b043a/Forever/BlizzardInterfaceCode/Interface/AddOns/Blizzard_APIDocumentationGenerated) contains the damage meter, enums, instance, encounter, LFG, group, unit and combat-log definitions. The matching [Blizzard meter implementation](https://github.com/reckhou/WoWBlzCode/tree/acb81d6eece0bd7f221456a634a54904ba0b043a/Forever/BlizzardInterfaceCode/Interface/AddOns/Blizzard_DamageMeter) corroborates list selection and per-source drilldown. Its three-window limit is a UI limit and supplies no retention bound.
- [Atraeau's generated API index](https://github.com/Atraeau/WoW-Addons/tree/main/docs/api) covers an earlier Forever build. The [Warcraft Wiki Forever overview](https://warcraft.wiki.gg/wiki/World_of_Warcraft:_Forever) gives platform context. [Blizzard's secret-value explanation](https://news.blizzard.com/en-us/article/24246290/combat-philosophy-and-addon-disarmament-in-midnight) is background for the shared architecture and is scoped to Midnight.
- [TomoDamageMeter](https://github.com/tomoaniki93/TomoDamageMeter) documents native sessions, pull comparison and dungeon recaps on Forever. [Forever DPS Meter](https://www.curseforge.com/wow/addons/forever-dps-meter) and [Forever Meter](https://www.curseforge.com/wow/addons/forever-meter) offer examples of native meter presentation. Their features are implementation claims and do not establish data access for every build and combat state.
- [ForeverLogs](https://www.curseforge.com/wow/addons/foreverlogs) illustrates an export workflow. [ForeverParse](https://www.curseforge.com/wow/addons/foreverparse) uses a separate file parser and reload. Neither is a dependency or source of live data for this project. No third-party code, assets or data were imported.
